RedScribe documentation

How to install, configure, run, and extend RedScribe, the self-hosted engagement, finding, checklist, and report manager for penetration testing teams.

These docs cover RedScribe 0.2.0-alpha.3. RedScribe is alpha software; read Alpha status & versioning before relying on it for a real engagement, and the Changelog for what changed in each release.

What RedScribe is

Section titled “What RedScribe is”

RedScribe is a self-hosted web application for running penetration testing engagements: scoping, checklist-driven testing, writing and reviewing findings, and exporting the client report. One instance serves one consultancy, and all engagement data stays on the server you run it on, encrypted per engagement. See the Sample report for what an export looks like.

How it works

Section titled “How it works”

A typical engagement starts with logging findings by hand, pulling them from the vulnerability catalogue, or importing results straight from Nmap, Burp Suite, or Nuclei. Each finding then moves through a real draft, review, and QA workflow, so nothing reaches a client before someone has actually checked it.

Once the engagement wraps, that same data becomes the client report, exported as Markdown, HTML, PDF, or Word from one shared source, so nothing drifts between formats. Throughout, findings stay on the server you run, encrypted per engagement with AES-256-GCM and keyed off a single instance root key.

What RedScribe is not

Section titled “What RedScribe is not”
  • Not multi-tenant SaaS. One instance serves one consultancy, and client companies get a restricted read only portal rather than their own tenant.
  • Not yet 1.0. RedScribe is early alpha. See Alpha status & versioning before relying on it for a real engagement.
  • Not a vulnerability scanner. It imports results from Nmap, Burp Suite, and Nuclei, but it doesn’t run scans itself.

RedScribe is source-available; see Licensing for what the license means day to day.
