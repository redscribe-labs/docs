## Why RedScribe

Most reporting tools built for penetration testers fall into one of two
camps: expensive platforms priced for enterprise budgets, or convenient
hosted services that never let your findings leave someone else's servers.
RedScribe sits in neither camp. It's source available, it's self hosted,
and it was built by a penetration tester on the workflow they run every
day, not a generic ticketing system repurposed for security work.

## How it works

That workflow starts with logging findings by hand, pulling them from the
vulnerability catalogue, or importing results straight from Nmap, Burp
Suite, or Nuclei. Each finding then moves through a real draft, review, and
QA workflow, so nothing reaches a client before someone has actually
checked it.

Once the engagement wraps, that same data becomes the report your client
actually reads, exported as Markdown, HTML, PDF, or Word from one shared
source, so nothing drifts between formats. Through all of it, your
findings stay on infrastructure you control, encrypted per engagement with
AES-256-GCM and keyed off a single instance root key.

## What RedScribe is not

- **Not multi-tenant SaaS.** One instance serves one consultancy, and
  client companies get a restricted read only portal rather than their own
  tenant.
- **Not yet 1.0.** RedScribe is early alpha. See [Alpha status &
  versioning](/start/alpha-status/) before relying on it for a real
  engagement.
- **Not a vulnerability scanner.** It imports results from Nmap, Burp
  Suite, and Nuclei, but it doesn't run scans itself.
