Two things need to happen before RedScribe is actually usable: it needs
its encryption key, and you need an account to log in with. This page
covers both. It applies to
[Installation Methods 1 through 3](/getting-started/installation/) (Docker
Compose). If you used Method 4 for local development, skip this page,
those steps are already built into it.

<Steps>

1. **Start everything**, if you haven't already (this already happened as
   part of whichever installation method you followed):

   ```sh
   docker compose up -d --build          # or: docker compose --profile tailscale up -d --build
   ```

2. **Generate the instance's root key**, the one master key that protects
   every engagement's sensitive data. Do this once, before creating any
   engagements:

   ```sh
   docker compose exec web python manage.py generate_root_key
   ```

   Copy the value it prints into `secrets/root_key.txt`, then restart so
   it picks it up:

   ```sh
   docker compose up -d web
   ```

   <Aside type="danger" title="Losing this key is unrecoverable">
   If this key is lost, every engagement's data becomes permanently
   unrecoverable, with no way back. Back it up the moment you generate it,
   with the same care you'd give any other master key. See the
   [Encryption model](/security/encryption/) for why.
   </Aside>

3. **Create your first admin account.** Pick whichever way suits you:

   - **Through the browser** (the easier option): visit `/setup/` on
     whichever address applies to your method, and fill in the form. This
     page only works before any admin account exists. Once you've created
     one, it redirects to the login page instead.
   - **From the command line**, useful for scripted deployments:

     ```sh
     docker compose exec web python manage.py bootstrap_superadmin --username admin --email admin@example.com
     ```

     You'll be prompted for a password (14 characters or more).

   Either way, your first login walks you through setting up two factor
   authentication, a QR code plus a confirmation code. Every local account
   goes through this, with no way to skip it.

4. Head to `/login/` (or you're probably already there).

</Steps>
