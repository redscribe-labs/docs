[**Download the sample PDF report**](/sample-report.pdf), a full,
38-page web application penetration test report for a fictional client,
"Umbrella Corporation," produced entirely from RedScribe's own report
pipeline.

<Aside type="caution">
This is demo content, deliberately watermarked **"AI GENERATED REPORT
CONTENT"** in the header of every page. The engagement, the findings, the
evidence, all of it is fictional and written to exercise every part of a
report, not a real assessment. Use it to see what RedScribe produces and how
a report is configured, not as a template to copy findings text from.
</Aside>

## What's in it

- A cover page, document control table, and engagement timeline.
- An executive summary, with an assessment overview, overall security
  posture, and a severity breakdown (bar chart + table).
- **10 findings**, Critical through Informational, each with a metadata
  table, description, impact, affected assets, evidence (including HTTP
  request/response code blocks), remediations, and references.
- **11 observations**, one per WSTG-style testing phase (information
  gathering, configuration, identity management, authentication,
  authorization, session management, input validation, error handling,
  cryptography, business logic, client-side testing).
- Scope & constraints, the assessment team's bios and qualifications, the
  testing methodology (7 phases), a CVSS v4.0 severity scoring guide, and a
  confidentiality & disclaimer section.

## Building a report like this

Everything below is real configuration on a real Report Profile, not a
special mode. Reproducing it is a matter of setting up the same pieces.

### Document template

The [Report Profile's](/admin/report-profiles/#document-template) Document
template is a straight top-to-bottom [structural and custom-tag
outline](/reference/report-template-tags/):

```
{{ cover_page }}
# Document Control          {{ document_control }}
# Engagement timeline       {{ engagement_lifecycle }}
{{ table_of_contents }}

# Executive Summary          {{ executive_summary }}
## Assessment Overview       {{ assessment_overview }}
## Overall Security Posture  {{ overall_security_posture }}
## Breakdown of Findings     {{ breakdown_of_findings }}

# Findings                   {{ finding_details }}
# Observations                {{ observations }}

# Scope and Constraints
## Scope of Testing          {{ scope }}
## Testing Conditions        {{ testing_conditions }}
## Assessment Team           {{ assessment_team }}

# Assessment Methodology     {{ testing_methodology }}
## Testing Phases            {{ testing_phases }}
## Severity Scoring Guide    {{ scoring_guide }}

# Confidentiality & Disclaimer  {{ confidentiality_disclaimer }}
```

`engagement_lifecycle`, `executive_summary`, `assessment_overview`,
`overall_security_posture`, `testing_conditions`, `testing_methodology`,
`scoring_guide`, and `confidentiality_disclaimer` are this profile's own
[text blocks](/admin/report-profiles/#text-blocks) (see below), not built-in
tags. A different profile is free to use entirely different slugs.

### Appearance

Set on the profile's [Appearance
tab](/admin/report-profiles/#appearance):

| Field | Value |
|---|---|
| Cover title | `Penetration Test Report` (overridden per-report, see below) |
| Classification label | `Strictly Confidential` (also overridden per-report) |
| Finding ID prefix | `F` |
| Body font | Plus Jakarta Sans |
| Monospace font | JetBrains Mono |
| Bullet character | `•` |
| Table header color | `rgb(42,42,42)` |
| Finding table layout | Table |

Severity colors were left at their built-in defaults (blank on the
profile), so the red/orange/green scale you see is RedScribe's own default
severity palette, not a custom one.

<Aside type="tip" title="The cover you see is a per-report override">
The cover title and classification label actually shown in the sample,
**"SAMPLE Web Application Penetration Test Report"** and **"AI GENERATED
REPORT CONTENT,"** aren't this profile's own defaults. They're set on
*this one report's* [Configure page](/user-guide/reports/#generating-a-report),
which overrides the profile's defaults for that single export. Every other
engagement using this same profile gets the profile's own "Penetration Test
Report" / "Strictly Confidential" cover instead.
</Aside>

### Finding structure

The findings use six active [content
sections](/admin/finding-structure/). A fresh instance starts with none
configured (aside from the built-in Affected Assets section below), so
this is this deployment's own admin-configured set, not a shipped
default:

| Order | Slug | Label |
|---|---|---|
| 10 | `vulnerability-description` | Description |
| 20 | `business-technical-impact` | Impact |
| 30 | `affects` | Affected Assets (built-in, see below) |
| 40 | `proof-of-concept` | Evidence |
| 50 | `remediations` | Remediations |
| 60 | `references` | References |

`affects` is the [built-in, protected Affected Assets
section](/admin/finding-structure/#affected-assets-is-a-built-in-protected-section).
It isn't rich text you author, it's positioned here but backed directly by
each finding's own **Affects** field.

### Text blocks

Eight profile-scoped [text blocks](/admin/report-profiles/#text-blocks)
supply the narrative prose the Document template above pulls in:

`assessment_overview`, `confidentiality_disclaimer`, `engagement_lifecycle`,
`executive_summary`, `overall_security_posture`, `scoring_guide`,
`testing_conditions`, `testing_methodology`.

Several of them (`engagement_lifecycle`, `testing_conditions`,
`testing_methodology`, `scoring_guide`) embed a table alongside their prose.
Text blocks are full rich text, not just paragraphs.

## Reproduce this sample

[**Download the seed script**](/seed-sample-report.py), a standalone Python
script that recreates the exact Report Profile, Finding Structure, engagement,
assessment team, and all 10 findings behind this sample, so you can export a
PDF yourself and compare.

<Steps>
1. Copy it onto your instance's host (wherever you'd run `docker compose`
   commands).
2. Run it through a Django shell:

   ```sh
   docker compose exec -T web python manage.py shell < seed-sample-report.py
   ```

   (`-T` disables the pseudo-TTY, needed for piped stdin under Compose.)
3. Open the seeded "Umbrella Corporation" engagement's **Report** tab,
   **Configure**, confirm the "Web Application" profile is selected, and
   export a PDF.
</Steps>

<Aside type="caution" title="Run this against a disposable instance">
The script creates real `Client`/`Engagement`/`Finding`/`ReportProfile`/`User`
rows. It's additive, not destructive, but it's meant for a throwaway demo
or staging instance, not production. It's safe to re-run: existing rows are
looked up by name/reference number/slug and updated in place rather than
duplicated. New demo user accounts are created with a placeholder password
(see the script's own header comment). Change it, and the placeholder
emails, before running this anywhere other than a fully disposable instance.
</Aside>
